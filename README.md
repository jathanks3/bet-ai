# BetAI

BetAI is an AI sports betting analyst — not just a chatbot. It rates a bet, gives you a clear verdict, and explains exactly why in plain English. BetAI is the first portfolio product built by [3Stone AI](https://3stone.ai), demonstrating the kind of software 3Stone AI builds for clients: fast, polished, and focused on a real outcome rather than a tech demo.

## What it does

BetAI supports three workflows, all producing the same kind of result — an overall rating, a verdict, a confidence score, and a leg-by-leg breakdown of what's helping and hurting the bet:

- **Analyze My Bet** — paste or type a bet slip (one leg per line) and get a full breakdown. Screenshot upload is designed in and coming soon.
- **Find a Bet** — ask BetAI about a team or matchup ("Best bet for Lakers tonight") and get a research-backed recommendation.
- **Build My Parlay** — pick a sport, leg count, and risk level, and BetAI assembles and rates a parlay for you.

Every result reports:

- Overall Rating & AI Confidence (0–100)
- Verdict: Bet / Lean / Pass / Avoid
- Biggest Edge & Biggest Risk, called out visually (green/red)
- Strongest and weakest leg
- Suggested improvements
- Source trust tier
- A responsible-gambling disclaimer

## Current status: mock data, real architecture

**No real APIs are connected yet.** Every analysis is generated by a mock service (`src/services/analysisService.ts`) using a bank of varied, randomized phrasing (`src/services/mockContent.ts`) so results don't feel repetitive or scripted. This is intentional: the goal right now is a polished, demo-ready product where the UI and data contracts are proven out before spending on real sports-data and AI providers.

The mock service is written behind a stable interface (`AnalysisService`) and always returns the same `BetSlipAnalysis` shape the UI already renders. Swapping in a real AI/sports-data backend later means replacing the inside of `MockAnalysisService` — the UI, types, and component tree don't change.

## Tech stack

- React 19 + TypeScript
- Vite (dev server & build)
- Plain CSS with a shared design-token theme (`src/styles/theme.css`) — no CSS framework
- ESLint (flat config) + `tsc` for type checking

No backend, no database, no auth, no payments — this is a static, client-only app by design at this stage.

## Getting started

**Prerequisites:** Node.js 20.19 or later (required by Vite 8 / ESLint 10 — Node 18 will not work), npm 10+.

```bash
git clone <this-repo-url>
cd bet-ai
npm install
npm run dev       # start the dev server (http://localhost:5173)
npm run build     # type-check and produce a production build in dist/
npm run preview   # serve the production build locally
npm run lint      # run ESLint
```

## Environment variables

Copy `.env.example` to `.env.local` and adjust as needed:

| Variable | Default | Purpose |
| --- | --- | --- |
| `VITE_APP_NAME` | `BetAI` | Display name shown in the app header |
| `VITE_MOCK_DELAY_MS` | `700` | Base artificial latency for the mock analysis service, so loading states feel realistic |

`VITE_API_BASE_URL` and `VITE_SPORTS_DATA_API_KEY` are reserved in `.env.example` for when a real backend is connected — they aren't read by any code yet.

Vite only exposes variables prefixed `VITE_` to the browser bundle. Never put real secrets in a `VITE_` variable — they ship to the client.

## Architecture

```
src/
  ui/                          Generic, reusable UI primitives (Card, Badge, Tabs,
                                SignalMeter, FindingCard, AsyncResult, ThinkingIndicator,
                                ErrorBoundary, UserMessage). Not BetAI-specific - these
                                are meant to be reused by future 3Stone AI products.
  features/betai/components/   BetAI-specific components (the three workflow panels,
                                BetAnalysisCard).
  services/                    Swappable business logic and data access
                                (analysisService, mockContent, teamCatalogService, env).
  types/                       Shared types (Finding, BetLeg, BetSlipAnalysis, etc.)
```

**One data model, three workflows.** `Finding`, `BetLeg`, and `BetSlipAnalysis` (in `src/types/betting.ts`) are the single shape every workflow produces. Analyze My Bet, Find a Bet, and Build My Parlay all render through the same `BetAnalysisCard` component — there's no separate rendering path per workflow.
